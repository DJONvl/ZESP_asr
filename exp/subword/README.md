# Эксперимент: CTC на субсловах Яндекса

Отдельная папка, чтобы не путать с рабочим проектом `C:\ZESP_asr\train`.
**Рабочую модель не трогает** — только читает данные и пишет свои чекпоинты.

## Гипотеза

Сейчас модель работает на **буквах** (36 классов). Проверяем, даст ли выигрыш
**субсловный** алфавит — готовый `subword_dict.txt` из модели Яндекса
(`rnnt-1.0.2`, 999 токенов, BPE с маркером `▁` начала слова).

Покрытие словарём нашего корпуса проверено (`train\check_yandex_dict.py`):

| | |
|---|---|
| наших слов | 144 533 |
| покрыто полностью | **100.0 %** |
| OOV-символов | 9 из 820 040 (0.00 %) |
| токенов на фразу | 13.1 (буквами 29.9) |

## Состав

| файл | что |
|---|---|
| `subword_dict.txt` | словарь Яндекса (копия, 999 токенов) |
| `swenc.py` | загрузка словаря, `encode(text)` → id, `decode(ids)` → текст |
| `swtrain.py` | обучение CTC с выходом 1000 + оценка на .128/.151 |
| `model_subword.pt` | лучший чекпоинт (по сумме CER двух валидаций) |
| `logs/` | вывод прогонов |

Данные берутся из `C:\ZESP_asr\train` (мел-кэши, meta) — копий нет,
27 ГБ не дублируются.

## Запуск

```powershell
cd C:\ZESP_asr\exp\subword
C:\ZESP_asr\train\.venv\Scripts\python.exe swtrain.py --epochs 12 --batch 16 --lr 3e-4 --golos 50000 --live-weight 10 --amp
```

Быстрая проверка (1 эпоха, 300 TTS, 200 Golos):

```powershell
... swtrain.py --tts-limit 300 --golos 200 --live-weight 10 --epochs 1 --batch 8 --amp
```

## Зачем Golos

999 классов при 25k TTS — это ~325 примеров на класс, слишком мало.
Golos farfield (125 ч, человеческая разметка) добавляет объём и языковое
разнообразие: `--golos 50000` берёт 50k фраз из `data\golos_farfield\meta.csv`.

Чтобы он не вытеснил живой домен, включён `--live-weight 10`
(WeightedRandomSampler) — живые фразы берутся в 10 раз чаще.


## Что важно знать

1. **Выход 1000 классов** против 36 — модель 3.08M против 2.59M (+19 %).
2. **Разреженность**: на 25k TTS × 13 токенов = 325k токенов на 999 классов,
   это ~325 примеров на класс против ~22 000 у букв. Основной риск эксперимента.
3. **Валидации зафиксированы**: .128 — те же 169 человеческих фраз
   (`live_meta.csv.bak`), .151 — 75 фраз (`live_nov23_v2_val.csv`); из train
   они исключены.
4. Запятых в словаре Яндекса нет — при кодировании они отбрасываются
   (в тексте и в метрике это надо учитывать).

## Результат

Прогон: 12 эпох, TTS 25k + Golos 50k + live ×10 (77k фраз на эпоху).

| модель | выход | .128 CER/WER | .151 CER/WER |
|---|---|---|---|
| `domain7` (буквы, рабочая) | 36 | **0.0350 / 0.1189** | **0.2799 / 0.5819** |
| `model_subword` (субслова + Golos) | 1000 | 0.4682 / ~0.9 | 0.4799 / ~0.8 |

Лучшая эпоха — 2-я (по сумме CER). Дальше модель переобучается на Golos и
живой домен проседает (на 6-й эпохе .128 CER 0.60).

**Вывод: при нашем объёме данных субслово проигрывает буквам в 13 раз** на
.128. Причины:

1. **Разреженность**: 77k фраз × 13 токенов ≈ 1M токенов на 999 классов —
   ~1000 примеров на класс против 22 000 у букв.
2. **Недообучение**: на 12-й эпохе loss 1.47 и продолжает падать; нужно 50+
   эпох, но это ~5 часов на прогон без гарантии.
3. **Малый корпус**: char-level при 25–35 часах аудио принципиально
   эффективнее — 33 класса учатся на порядки быстрее, чем 999.

Модель декодирует осмысленно (не баг): «включи свет в спальне» → «включи свет
… в … спальне» — лишние токены и путаница окончаний.

## Итог эксперимента

Направление закрыто: **буквенный алфавит остаётся**. Субслово имеет смысл при
сотнях часов и/или языковой модели — то есть не в нашей текущей конфигурации.
Рабочий `train` не менялся.


## Если выигрыш есть

Интеграция в C-движок (не сделана специально, пока не подтверждено):

1. `export_runtime.py` — писать таблицу токенов вместо букв;
2. `asr.c` — декодер собирает строку из токенов, `▁` → пробел;
3. `vocab.txt` → список субслов; ZESP получает обычный текст, правок не нужно.

Если выигрыша нет — эксперимент закрывается, рабочий `train` не меняется.
